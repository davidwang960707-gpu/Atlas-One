## 一句话定位

**Atlas One 是一个面向企业场景的 B/S 数智员工平台。**

它不是再做一个聊天窗口，也不是把 CLI 搬到 Web 页面里，更不是让每个用户在自己的本机上各自运行一套 Agent。Atlas One 的核心，是把 Agent 能力组织成可管理、可控、可信的「数字员工」，并通过企业级平台统一提供访问、权限、审计、调度和治理。

简单说：**个人工具解决“我怎么用 AI”，Atlas One 解决“企业怎么安全、稳定、可控地使用一支由平台统一模型服务驱动的 AI 数字员工队伍”。**

Atlas One 以**编排、协作、交付**为核心设计理念，面向 OPC 和初创团队，帮助团队高效管理数智员工队伍，把 AI 能力落到明确任务、协作过程和可交付的业务结果上。

## 这是什么

Atlas One 是一个正在预览中的企业级数智员工平台。

在 Atlas One 里，Agent 不只是一个可以聊天的模型窗口，而是被平台化管理的数字员工：

- 有岗位身份：姓名、部门、职责、工作边界
- 有能力配置：技能、知识库、工具权限、任务范围
- 有运行约束：哪些能做、哪些不能做、哪些需要审批
- 有过程记录：任务、对话、操作、结果可以追溯
- 有平台治理：招聘、上岗、调度、绩效、停用由平台侧统一管理

这也是 Atlas One 的产品边界：我们不只追求「回答得聪明」，更关注「执行是否安全、权限是否清楚、过程是否可审计、结果是否能被企业信任」。

## 核心理念

Atlas One 围绕三个关键词设计：

- **编排**：把复杂任务拆解给合适的数字员工，让能力、上下文和任务路径有序流转。
- **协作**：让不同岗位的数字员工围绕同一业务目标接力工作，而不是各自孤立回答。
- **交付**：以最终业务结果为导向，关注任务是否完成、产物是否清楚、过程是否可追踪。

对 OPC 和初创团队来说，Atlas One 希望承担的是一套轻量但可靠的数智团队管理入口：不用从零搭建模型、权限和运行环境，就能让数字员工围绕真实业务目标开展工作。

## 模型服务

Atlas One 对外试用阶段统一提供小米模型服务。

用户不需要在本地安装模型、不需要自己维护推理服务，也不需要在浏览器里配置各类模型 Key。模型能力由平台侧统一接入、统一调度、统一治理，试用者只需要进入页面体验数字员工本身。

这也是 Atlas One 坚持 B/S 架构的重要原因之一：企业级 AI 能力不应该散落在每台个人电脑上，而应该由平台统一提供稳定、可控、可追踪的模型服务。

## 为什么不是本地运行

本地 Agent 工具很适合个人开发者快速试验，但企业真正落地时，会遇到一组绕不开的问题：

- 凭证散落在个人电脑上，难以统一管理
- 文件、会话、记忆和日志分散在本地，难以审计
- 工具权限依赖个人配置，边界不够清晰
- 高危操作缺少统一审批与追踪
- 多人协作时缺少组织视角和责任归属
- 员工离职、换岗或设备更换时，数据与权限交接复杂

Atlas One 选择 B/S 架构，就是为了把这些问题收回到企业平台层统一处理。用户通过浏览器访问，运行、权限、数据、审计和治理由服务端集中承载，企业可以更清楚地知道：谁在用、用哪个数字员工、做了什么、有没有越权、结果在哪里。

## 和普通 Agent WebUI 的区别

| 维度 | 普通本地 Agent WebUI | Atlas One |
|---|---|---|
| 部署方式 | 本机运行、个人配置 | B/S 架构、服务端统一承载 |
| 模型服务 | 用户自行配置模型或 Key | 平台统一提供小米模型服务 |
| 使用对象 | 单个用户、单个 Agent | 企业团队、多名数字员工 |
| 安全边界 | 依赖本地环境和个人习惯 | 平台统一权限、审计和控制 |
| 数据归属 | 文件、会话、记忆多在本地 | 企业侧集中管理和追踪 |
| 能力组织 | 工具和模型围绕个人使用 | 技能、知识、工具围绕岗位配置 |
| 管理视角 | 个人工作台 | 数字员工队伍与组织治理 |
| 信任机制 | 相信使用者自己管好 | 平台让过程可见、权限可控、结果可追溯 |

所以 Atlas One 的重点不是「把 Agent 放进浏览器」，而是把 Agent 能力变成企业能放心使用、能持续管理的数字劳动力。

## 在线试用

公网试用链接稍后补充。

预览版会优先开放核心体验：进入平台、选择或调度数字员工、发起任务、观察流式响应、查看员工身份与任务上下文。当前阶段更重视真实可用的主路径，而不是把所有企业功能一次性铺满。

后台管理功能暂不对外开放。试用环境会由平台侧预先配置好数字员工、模型服务和基础运行策略，大家先体验前台使用流程即可。

欢迎大家试用时重点观察：

- 数字员工的岗位感是否清楚
- 不同员工之间是否有明确能力边界
- 平台是否比普通聊天工具更像企业工作台
- 哪些地方已经让人感觉安全、可控、可信
- 哪些地方还停留在 demo 感，需要继续打磨

## 当前状态

Atlas One 仍处于预览阶段，功能、界面和部署方式都会持续变化。

现在的目标很明确：先证明「B/S 数智员工平台」这件事成立，而不是急着宣布一个完美大而全的企业套件。员工管理、权限边界、任务调度、协作流程、操作审计、知识库和成本治理会由平台侧逐步完善，但不会在当前公开试用中开放后台管理入口。

## 试用说明

目前试用环境部署在资源有限的虚拟机上，所以体验时可能出现：

- 首次访问稍慢
- 高峰期响应变慢
- 大任务执行时间较长
- 偶尔需要刷新或稍后再试

简单说：欢迎来试，欢迎认真挑刺，也请先对这台预览机温柔一点。

如果页面短暂不可用，大概率不是项目消失了，而是虚拟机正在努力把前端、后端、数据库和 Agent 运行环境一起扛住。

## 为什么只放 README

这个仓库当前只作为 Atlas One 的项目入口页使用，暂不公开完整源码。

原因不是故作神秘，而是项目还在快速重构和验证中。尤其是运行安全、工具权限、企业数据边界、部署隔离和多用户治理这些部分，如果没有整理清楚就直接公开，反而容易误导使用者。

后续如果拆分出稳定模块、示例工程、SDK、设计系统或部署模板，会优先在这里同步入口。
